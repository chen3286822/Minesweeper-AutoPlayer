# Minesweeper-AutoPlayer · 扫雷自动操作工具

Winmine auto-play tool。

一个使用 C++ 和 Windows API 编写的经典扫雷自动操作实验。通过屏幕像素识别棋盘中的数字与格子状态，根据邻格规则推断可点击位置或待标记的雷，再向游戏窗口发送鼠标消息。

项目原名 `chen-Hook`，保留了早期 Hook 实验的工程名和代码，但当前执行路径中的 `SetWindowsHookEx` 调用已注释；实际自动扫雷由窗口查找、屏幕采样和消息发送完成。

## 实现内容

- 使用 `FindWindow` 定位经典扫雷窗口。
- 使用 GDI 截取棋盘区域，按预设颜色识别数字、空格和未打开的格子。
- 检查数字周围的未打开格子和旗子，执行基础排雷规则及部分相邻约束判断。
- 通过 `SendMessage` 发送左键、右键和组合点击消息。

这是针对特定经典扫雷界面写的实验，不是通用图像识别框架，也不保证解出所有棋局。

## 工程结构

```text
Hook/Hook.sln              # Visual Studio 解决方案
Hook/Hook/                # 控制台入口，调用 setHook / unsetHook
Hook/HookDll/             # 棋盘识别、推断与窗口操作实现
Hook/扫雷颜色.txt          # 数字颜色记录
Hook/winmine.exe          # 仓库保留的历史程序文件
```

主要实现位于 `Hook/HookDll/HookDll.cpp`，阅读时可以从 `setHook()`、`sweepMine()`、`updateMap()` 和 `checkFirst()` 开始。

## 构建与使用准备

- 平台：Windows，项目提供 `Debug|Win32` 和 `Release|Win32` 配置。
- 当前工程指定 Visual Studio 2017 的 `v141` 工具集和 Windows SDK `10.0.16299.0`。
- 打开 `Hook/Hook.sln`，检查两个项目的工具集、SDK 和依赖，再构建控制台程序及 DLL。使用其他版本的 Visual Studio 时需要自行处理迁移。
- 运行前需要准备与代码匹配的经典扫雷版本，棋盘尺寸为 **16 行 × 30 列**，格子边长按 **16 像素**处理。
- 当前窗口查找使用的类名为“扫雷”。其他语言或新版扫雷界面不一定匹配。

程序依赖已经打开的数字进行推断。尝试时应先打开棋局并手动展开部分格子，保持游戏窗口可见且不要遮挡；再运行编译后的控制台程序。当前循环没有实现完整的胜负判定和自动退出，需要手动结束控制台进程。

## 适用范围

- 棋盘大小、颜色和窗口偏移均有硬编码，系统主题、缩放比例或游戏版本变化都可能导致识别错误。
- 系统版本判断和坐标调整是历史实现，不能据此保证现代 Windows 上可直接运行。
- 程序会向匹配到的窗口发送操作消息，并修改其标题；仅在自己控制的本地测试环境中使用。
- 仓库中的历史二进制文件未在本次文档整理中运行或重新验证。建议先阅读源码，再自行构建和检查。
